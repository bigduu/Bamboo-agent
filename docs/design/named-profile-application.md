# Named profiles on the strict local Child route

The server's actual Child creator resolves `subagent_type` from one immutable
Global/active-Project catalog observation. Project definitions retain the
existing precedence; a known conflicting/invalid name or anonymous invalid
candidate rejects creation. An unavailable catalog/Project never permits a
fallback. Only a truly unknown name in an available observation uses legacy
role routing. Worker embeddings without this server catalog producer retain
their existing behavior.

A selected definition applies its exact body after the configured global
Child base and before the existing child delegation contract. It is shipped
as the host Child's System message to the actual worker/provider. The profile
model hint supplies the bound provider/model, ahead of legacy role routing
and below an explicit existing `create.model` selection;
single-call reasoning effort remains the Child's own ordinary selection.
The selected definition remains host-private; SubAgent schema describes the
selection without publishing its body. Explicit authenticated System-prompt
inspection retains the existing product behavior.

Known profiles require the existing fresh, default-current-exe, local Bamboo
worker route. Creation adds a bounded required packet when none was supplied:
the exact task brief/objective and ordinary evidence expectation, with empty
optional history and no invented user decisions or constraints. A supplied
packet keeps its complete required fields. Existing fit/capability checks
reject before persistence; no remote/custom-worker support is claimed.

Only the five native names Read/Glob/Bash/Edit/Write are supported declarations
in this first application slice. Other/composition names reject. Profile
allow/deny narrows the actual Host-owned #1361 ceiling, configured disables,
inherited Child denies, permission checks, workspace/Project validation and
typed readOnly. Project manifests have no additional tool-name policy field;
this does not invent network/secret grants. Explorer/reviewer names impose an
additional read-only restriction, even for a Project override; the name never
attests builtin provenance or grants authority. Root's direct orchestration
tool fence is separate from its configured delegation authority.

The existing Child metadata stores safe selection identity/revision plus the
frozen model, tools, readOnly, lifetime/Project and composed-prompt digest.
It stores no separate role body. Subsequent runs validate these observations
and narrow with current Host policy without reopening the role file. Changing
the file affects a later creation, not this selected Child. SubAgent Update
rejects role/initial assignment/model/effort replacement; ordinary title and
additive steering messages remain supported.

This is not a new sealed storage protocol or all-writer fence: authenticated
generic Session PATCH, arbitrary external full-save/metadata replacement and
new retry/recovery guarantees remain outside this consumer slice. It does not
close all #909/#791 acceptance, install the #1315 default package, or add
session-scoped role enumeration to the static tool schema. The existing safe
authenticated named catalog remains the discovery surface.

Prepared validation uses real files and an actual same-source `serve`/default
current-exe worker with only scripted SSE model responses: Project precedence,
private prompt/model in real provider requests, typed readOnly and actual Write
denial/success, Host narrowing, source reload stability, unknown fallback and
invalid/duplicate rejection before Child persistence. No execution is claimed
until the coordinated Cargo gates complete.
